## 형식

`태그: 내용` — 태그는 아래 표의 영문 소문자, 내용은 한국어로 짧게 쓴다. 본문은 쓰지 않는다.

예: `docs: 의존성 방향 명확화`, `setting: expo sdk 57 업그레이드`

| 태그     | 의미                     |
| -------- | ------------------------ |
| feat     | 새로운 기능 추가         |
| fix      | 버그 수정                |
| ui       | UI 컴포넌트 추가/수정    |
| design   | 스타일링 변경            |
| docs     | 문서 수정                |
| refactor | 코드 리팩토링            |
| test     | 테스트 코드              |
| chore    | 패키지 매니저, 기타 잡일 |
| setting  | 환경설정, config 수정    |
| build    | 빌드 관련                |
| asset    | 리소스 추가/교체         |
| comment  | 주석 작업                |
| rename   | 파일/폴더명 변경         |
| remove   | 파일 삭제                |
| hotfix   | 긴급 버그 수정           |
| release  | 릴리즈                   |

- 새 공용 컴포넌트를 추가한 커밋은 `ui:` 또는 `feat:`를 쓴다.
- `Co-authored-by:` 같은 트레일러나 에이전트·도구 이름을 넣지 않는다.

## 커밋 나누기

- 커밋 하나에는 한 가지 목적만 담는다.
- 함께 바꾸지 않으면 빌드가 깨지거나 문서가 없는 파일을 가리키게 되는 변경은 같은 커밋에 둔다.

## 주의

- 사용자가 커밋을 명시적으로 요청하기 전에는 커밋하지 않는다. 메시지와 포함할 파일만 제안한다.
